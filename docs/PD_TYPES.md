# Покрытые типы персональных данных

Сервис распознаёт 30 типов персональных данных. Каждый тип — стабильный
wire-идентификатор (`pd.Type`), который появляется в конфигурации, логах и
метриках. Полный каталог — в `internal/pd/types.go`.

Каждый детектор регистрируется в общем реестре (`detect.Register`) и обязан быть
stateless и безопасным для конкурентного использования.

## Стратегии маскирования по умолчанию

Стратегия по умолчанию задаётся в `config.defaultTypeRules()`:

- `FIO` → `initials` (кириллическое ФИО → «И. И. И.»).
- `CARD_HOLDER` → `initials_latin` (латинское имя → «I. I.»).
- `CVV` и `PIN` → `stars_all`, с `requires_companion: ["CARD_NUMBER"]`.
- Все остальные типы → `stars_keep2`.

Правило `requires_companion` для `CVV` и `PIN` означает: значение маскируется
только если в том же payload найден номер карты. Одинокий PIN или CVV — не
персональные данные и не маскируются.

## Как работает маскирование

`stars_keep2` держит первые и последние два алфавитно-цифровых символа и
заменяет остальные на `*`. Разделители (пробелы, точки, дефисы, `@`, скобки)
не считаются алфавитно-цифровыми и сохраняются как есть, поэтому маска остаётся
выровненной с исходным текстом посимвольно. Кириллица обрабатывается по рунам
(двухбайтовая буква не портится байтовым циклом).

`stars_all` прячет все алфавитно-цифровые символы — для коротких секретов, где
даже два видимых символа утекли бы заметную долю энтропии.

`initials` сводит каждое слово к «X.», разделённому пробелом, с сохранением
дефиса в двойной фамилии («Петров-Водкин» → «П.-В.»). Уже сокращённый ввод
(«Иванов И.И.») нормализуется к тому же каноническому «И. И. И.». `initials_latin`
— то же для латинского алфавита.

## Приоритеты при пересечении спанов

Когда детекторы находят пересекающиеся спаны, побеждает один по правилу
`detect.Resolve`: длиннее → выше приоритет типа → выше уверенность. Приоритет
типа задан в `pd.Type.Priority()`: длинные однозначные идентификаторы
(`CARD_NUMBER`, `BANK_ACCOUNT`) выше коротких числовых, чтобы CVV внутри номера
карты не разбивал карту.

## Отладка детекции

`POST /admin/detect` возвращает отчёт о том, что нашли детекторы: категории,
количества и байтовые смещения. Найденные значения не возвращаются никогда —
эндпоинт рассчитан на вызов поверх реальных данных. Применяются правила системы
`enabled` и `min_confidence`; правило `requires_companion` здесь не применяется
(оно относится к этапу маскирования и живёт в движке).

Пример реального вывода для текста «Клиент Иванов Иван Иванович, паспорт 4509
123456»:

```json
{"bytes":79,"count":2,"types":{"FIO":1,"PASSPORT":1},"spans":[{"type":"FIO","start":13,"end":51,"len":38,"conf":0.98,"src":"fio","hint":"full"},{"type":"PASSPORT","start":68,"end":79,"len":11,"conf":0.98,"src":"passport","hint":"series_number"}],"system":"default"}
```

## Ложные срабатывания

Сервис намеренно не маскирует имена известных людей и адреса отделений банка,
если они не являются персональными данными клиента. Например, «Читал Александра
Пушкина в отделении банка на улице Вавилова, дом 19» — поэт и адрес отделения
не являются ПД клиента и должны остаться нетронутыми; это проверяется в
`scripts/smoke.sh`.
